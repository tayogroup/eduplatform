# The prompt this build was made from (improved)

The request arrived as six words, after Grades 1 and 2 had been built,
verified, deployed and routed:

> now build grade 3 on the same kit

Below is the version that states what those words assume, what they leave
open, and the checks that decide whether it was done. It is the Grade 2
prompt (`../grade-2-app/PROMPT.md`) with the Stage 3 parts stated, and it is
written so it can be reused for Stage 4 by changing the named things.

---

## Build a Grade 3 Computing standalone lesson course for Ehel Academy, on the Grade 1–2 kit

### What to build

A **standalone lesson build** at `src/prototypes/ehel-academy/computing/grade-3-app/`,
generated by the kit the earlier grades were generated by (`../lesson-kit/`),
wired by the shared pipeline in `mathematics/lesson-app-tools/` and gated by
its `check-lessons.py` and the kit's `check-coverage.py`. One self-contained
HTML page per lesson plus a hub, the design and voice of the earlier builds
unchanged.

**"On the same kit" means the kit is extended, not forked, and the earlier
grades are the proof.** Stage 3 asks for things Stage 2 has no renderer for —
concise algorithms, the steps that repeat, predicting a change, machines with
an input and an output, tidying a program, several scripts at once with a
static object, a number inside a block, a physical device with inputs and
outputs, three views of one table, a spreadsheet, a filter, a cipher — so
`lib/computing.js`, `_rules.py`, `build-lessons.py`, `build-hub.py` and
`check-coverage.py` all grow. Every growth must leave Grades 1 and 2 exactly
as they were: rebuild both on the extended kit and require their `LESSON`
data blocks to be identical, page for page, before building anything at
Stage 3, and again after the last fix.

**Design, style and UI: unchanged.** No new hue; Stage 3 styles are added to
`computing.css` under a marked heading.

### The content: Cambridge Primary Computing 0059, Stage 3, all of it

- The framework file exists (`src/curriculum/cambridge-computing-0059.json`);
  Stage 3 has **36** objectives across the same five strands. Nothing under
  `computing/grade-3/` (the Word-pack course) is read or written.
- Organise by **strand**, fourteen lessons: follow, edit, correct; concise
  algorithms; think it through; input machines; tidy programs; many things
  at once; press, shake, clap; mistakes make programs better; data problems;
  spreadsheets; networks around us; secret codes; systems, inputs and files;
  machines, things and robots.
- **Every step names the objective codes it exercises**; the builder refuses
  a code Stage 3 does not publish; the gate fails if any of the 36 is reached
  by no step. Behaviours, not labels: "concise" is a step the child cuts and a
  scene that still completes (3CT.02); "repeated" is a run the child taps and
  the page folds (3CT.03); "predict" is answered before the change is applied
  (3CT.05); an input-output algorithm is a machine the child builds and feeds
  (3CT.08); "tidy" is proved by running the shorter program and getting the
  same behaviour (3P.01); "reset" is a sprite that really starts displaced
  (3P.02); "at the same time" is two scripts stepping in the same beat
  (3P.03); a number inside a block is a chip the child changes (3P.05); a
  device is a board with inputs the child presses (3P.06, 3P.10); a cell is
  found by letter and number and formatted for its purpose (3MD.04, 3MD.05);
  a filter is built from chips and counted (3MD.06); a cipher is written and
  read against the 1 = a strip (3DC.05).
- **Computed beats claimed.** Every key the data can decide is computed by
  `_rules.py` and its JS mirror: machine outputs, walk ends, codes, filter
  counts, chart and view keys, tidy equivalence, the repeated run, the
  spreadsheet's unique cell — refused by the builder and re-checked by the
  gate on the shipped pages.
- Language: British English, seven-to-eight-year-old reading level, the
  learner addressed as "you". Home projects unplugged.

### Wiring and progress

- `app.config.json`: grade 3, stage 3, `courseKey` `ehel-comp-g03`,
  `progressUnitPrefix` `l`, `fromParam` `comp3`, hub `g3-index.html`, remote
  `Ehel Primary/app/computing/grade-3-v2`; `objectiveFloors` recorded at the
  measured value after the first green build.
- The same pipeline in the same order as Grades 1 and 2.
- Do NOT deploy Grade 3, do NOT redeploy Grades 1 or 2, and do NOT route:
  all owner decisions to be asked for.

### Definition of done

1. Grades 1 and 2 rebuilt on the extended kit: pipeline and gates green,
   `LESSON` blocks identical to HEAD, 8 of 8 and 10 of 10.
2. `build-lessons.py` builds 14 pages with 0 refusals and reports 36/36;
   `check-lessons.py` and `check-coverage.py` exit 0.
3. Every inline classic script of all three grades parses under `node --check`.
4. The gate is mutation-tested at Stage 3, pages restored byte-identical: a
   lesson losing an objective, an unpublished code, a machine keyed wrong, a
   tweak that misses the target, a cipher answer that disagrees with the code,
   a filter count keyed wrong, a tidy program that does something different, a
   trim whose expect is not what is left, a repeated run that does not repeat,
   a view keyed against its columns, a spreadsheet find with two answers, a
   device program with no when block first, a lesson under its floor, a
   what-if with no key.
5. Every step of every lesson of ALL THREE grades is driven to completion in a
   browser; dot rail, header and shelf agree; only the five platform-module
   404s in the console; no step overflows at 375px.
6. A README beside the build; the kit README's step-kind table updated.

### What is deliberately out of scope

Deploying or routing; recorded narration; a Scratch embed; anything at
Stage 4; a human reading of the content.

---

### Why six words needed this

- "the same kit" is a constraint on the KIT: Stage 3 cannot be authored in
  Stage 2's step kinds, so the kit has to grow, and the only thing that makes
  growing it safe is a proof that the live grades did not move. The prompt
  states the proof.
- "grade 3" is Stage 3 of 0059 — 36 objectives with a different emphasis
  (efficiency, decomposition, input and output, initialisation, parallel
  scripts, physical devices, spreadsheets, ciphers, the Internet of Things,
  manufacturing robots) — so the lesson plan is stated rather than inherited.
- What was NOT said (deploy, route, redeploy the earlier grades) is stated as
  not done, because each of the earlier flows did those only on an explicit
  instruction.
