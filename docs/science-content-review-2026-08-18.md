# Science course — proofreading review (2026-08-18)

Scope: every learner-facing string in `src/prototypes/ehel-academy/science/grade-1..8/data/**` — 53 units, 8 placement exams, 8 grade capstones, 8 course manifests, ~732K characters of teaching text. Method: ten reviewers each read an assigned slice blind (one per grade for Stages 1-6, split in two for Stages 7-8, whose units are roughly 60% larger); two of them further split their own range across sub-agents rather than reading it directly, and those sub-results were collected and merged in afterward. A consolidation pass mechanically verified all 664 surviving quotes against the source files (0 broken). `npm run check:science` passes clean on the result.

Science's built JSON is **generated** (extract → build → check, from Word source packs), and CLAUDE.md is explicit that it must never be hand-edited — "fix the builder instead." That ruled out the direct-JSON-edit approach used for the sibling Mathematics review, and shaped everything below.

## Fixed at the builder — five systemic classes, ~1,700 instances

All in `tools/build-ehel-science-runtime.js`. Each is a rule, not a one-off edit, so it applies identically across every grade and survives the next `build:science`.

1. **Prompt/answer shift in `realProblems`/`reasoningPrompts`** (the dominant defect — reported independently by nearly every reader as "the answer belongs to the *next* question"). Root cause: a section-level preamble sentence ("Use what you know to solve these real problems.", "These questions make you think harder.", "Apply what you have learned to real situations.") was kept as if it were the section's first real task, because nothing excluded it. That gave item 1 a fake prompt paired with item 2's real answer, and so on down the array, with the last item falling back to a generic "Work through the task…" filler because the answer-key list had run one short. Confirmed against every Practice document in the content model: two regex alternatives (`Use what/your/the…`, `These questions/are/make/need/require…`, `Apply what…`) cover all 61 instances of this preamble across the whole course, none colliding with a real question.
2. **Leaked section headers and vocabulary intros in `outcomes[]`** (surfaced twice — once as a nonsense outcome, once in `selfAssessment[]` via the "I can…" template). The extractor's "able to do" section label runs on past the objectives list to the next heading, and for many documents no next heading is ever detected, so the label silently swallows the entire rest of the lesson — the glossary, every concept's body text, sometimes hundreds of blocks. `outcomeList()` now requires an outcome-shaped opening verb (the same list already used by the existing verb-led fallback), which holds in every unit that has real objectives and only falls through to that fallback for the few that don't.
3. **Second-person pronouns inside first-person self-assessment** ("I can use what *you* know…", "I can explain… using *your* own examples"). `selfAssessment` was built by prefixing "I can" onto the first word of each outcome and touching nothing else. 81 lines mixed person mid-sentence. Ported the same `toFirstPerson()` conversion used for the Mathematics review.
4. **Game rounds silently stale after a reviewer correction.** `games.games[].rounds[]` is built by copying straight from `assessment.questions`, but that copy happened *before* `script-review.json` overrides were applied to the assessment — so a corrected quiz answer landed in the quiz and never reached the four game rounds built from the same question. This wasn't visible until it was used to check the safety fix below and the game copies still showed the old wrong answer. It silently affected all 103 pre-existing `Assessment Question` overrides from the 2026-08-01 reviewer pass, not just the one found here. Fixed by applying just that category's corrections before `gameData()` runs.
5. **Placeholder worked-example titles** ("Guided example 5", "Guided example 6"…) — derived a real title from the question text instead, the same technique the Mathematics builder uses.

Plus one narrow extension: the reference "common mistakes" card whose first entry was literally the source table's own column headings ("The Mistake" / "Why it is wrong") — an existing filter already caught "Common mistake" as a header string but not "The Mistake"; added.

**Stale reviewer-workbook overrides.** `science/data/script-review.json` carries hand corrections from a 2026-08-01 reviewer pass, merged on top of every rebuild. 14 `outcomes` overrides, 40 `Real Problem`/`Reasoning Prompt` overrides, and 15 `Self Assessment` overrides were carrying the *old, broken* content forward verbatim — an override always wins over freshly-computed output, so leaving them in place would have silently undone fixes 1-3 above for the specific units they touched. None were genuine hand-edits to that content (the values were byte-identical to what the pre-fix builder produced); all 69 were stripped so the corrected builder logic can reach every unit.

## One safety-critical content fix

Grade 2 Unit 1's assessment asked *"In a flood, where is the safest place to go?"* and keyed the answer to **"into the fast water"** — the single most dangerous option offered, contradicting the unit's own teaching two paragraphs earlier ("the safest thing is to move to higher ground… and stay away from fast-moving water"). Corrected via a `script-review.json` override (answer + explanation) rather than a builder change, since this is unique wording, not a pattern. Confirmed the fix now also reaches all four copies in the unit's games, which fix #4 above made possible.

## Left open — 500 findings, documented in `docs/science-content-review-2026-08-18-findings.json`

Every quote there is mechanically verified as an exact substring of the live JSON, so the file is a reliable starting point for a future pass rather than a re-read of the whole course. Breakdown of what's in it:

- **~77 — duplicated/mismatched activity materials or vocabulary examples.** A unit's later "Observe:"/"Sort:" activities frequently copy the materials list from an earlier, unrelated activity in the same unit (their own steps need nothing from that list); several vocabulary entries in a unit share one identical example sentence that doesn't actually illustrate the specific word.
- **~62 — exploration linked to the wrong concept.** `explorations[].explanation`/`modelType` is assigned by array position against `concepts[]`, and in several units (Grade 5 Units 4-5 especially) the positions are off by one, so an investigation about refraction shows the reflection/mirrors concept text, etc.
- **~56 — placeholder or bare-fragment worked-example titles** beyond what the systemic fix could reach (a numbered heading like "1: Comparing shadow to object" that never carried the word "Worked Example" in the source, so nothing recognisable to derive a title from).
- **~49 — dropped source tables**, leaving a concept or model answer ending on a colon ("Here is a tally chart…:") with nothing following. Traceable in most cases to `outputs/science-content/science-content-model.json`, same as the equivalent Mathematics finding — a builder gap, not a missing source.
- **~17 — hints referencing the wrong vocabulary terms** (a fixed pair of terms repeated across every practice/fluency/real-problem item in a unit regardless of that item's actual topic).
- **15 — genuinely wrong science content**, the highest-value remainder for a follow-up pass: Grade 1 Unit 2 and Grade 5 Unit 1 each have a vocabulary "example" that's actually the definition of a *different* term (Leaves ↔ Stem, Nutrients ↔ Root); Grade 5 Unit 2's reference table has three terms (Feature/Nectar/Pollen) holding garbled comparison-table fragments instead of definitions, with Pollen defined two different, contradictory ways in the same unit; Grade 8 Unit 7 states an active 12-year-old's daily energy need as "2000 to 2200 kilojoules" when that figure is correct in **kilocalories** (understating true need roughly 4x).
- **One contained, unfixed extraction defect**: Grade 3 Unit 3's Practice document prints every section's answer key (A through E) as a single table cell holding all its numbered answers concatenated ("✅ Section D Answers 1. … 2. … 3. …") rather than as separate rows. The existing table-cell parser doesn't split this format, so the whole numbered block lands on that section's first question and the rest fall back to the generic filler. Unique to this one unit in the whole 53-unit corpus — not attempted here since a general parser change carries more risk than the single-unit payoff justifies; a `script-review.json` override for this unit's five affected items would be the lowest-risk fix.
- The remainder is grammar, punctuation, US spelling, and clarity items below the threshold that justified a builder rule.

## Why

Same rationale as the Mathematics and English reviews: a fix that only lives in the built JSON is discarded by the next `build:science`, and Science rebuilds routinely (the extract → build → check loop is the documented workflow for this subject, unlike Mathematics). Every fix here is either in the builder itself or in the reviewer-override file the builder is designed to merge — both survive a rebuild; nothing was hand-edited in `science/grade-*/data/`.
