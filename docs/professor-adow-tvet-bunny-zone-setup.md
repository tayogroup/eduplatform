# Creating the Professor Adow TVET Bunny zone

What has to exist before `tools/upload-adow-to-bunny.js` will send anything,
and how to prove it worked. Written 2026-09-24, when the school had never been
uploaded once.

Everything else about this school is built: 8 lessons, 62 performance criteria,
a rendered film and a slide deck. The only thing between that and a link the
client can open is this page.

---

## Why it is blocked right now

`src/prototypes/professor-adow-tvet/school.config.json` still reads:

```json
"storageZone": "TODO-adowtvet",
"cdnHost":     "TODO.b-cdn.net",
"appDomain":   "TODO",
```

and `.env` has no `BUNNY_TVET_KEY`. The uploader refuses while any of those
three fields begins with `TODO`, and refuses again on `--confirm` with no key.
That is the scaffolding working, not a fault: a zone name is cheap to decide
and expensive to change, because version and media paths on Bunny are cached
for about a year and a 404 minted by a premature probe **cannot be purged with
the key in `.env`**.

---

## A. Four values to decide first

| value | what it is | suggested |
| --- | --- | --- |
| storage zone name | globally unique across Bunny | `adowtvet` |
| storage zone password | generated by Bunny, goes in `.env` | — |
| pull zone hostname | what `cdnHost` becomes | `adowtvet.b-cdn.net` |
| `appDomain` | the eventual public hostname | a Professor Adow domain |

Two honest notes on the last one. **`appDomain` is enforced but not yet
consumed**: the uploader's guard refuses while it says `TODO`, and nothing else
reads it today. Put the real intended hostname in anyway — it is a Phase 0
decision and the guard exists to stop it being forgotten. And it should be a
**Professor Adow** domain, not an Ehel subdomain: this school is deliberately
separate, which is the whole reason it has its own zone, its own catalogue and
its own consumer record.

## B. In the Bunny dashboard

1. **Storage → Add Storage Zone.** Name it `adowtvet`.

   **The region must be Falkenstein (DE), Bunny's main region.** This is the
   one step that cannot be fixed later without re-uploading. The uploader PUTs
   to `storage.bunnycdn.com`, hard-coded:

   ```js
   method: "PUT", host: "storage.bunnycdn.com", path: `/${ZONE}/${remote}`
   ```

   A zone whose primary region is anywhere else answers on its own endpoint
   (`ny.storage.bunnycdn.com` and so on) and every upload would fail against
   this host. Replication to other regions is fine and additive; the *primary*
   is what matters.

2. **Copy that zone's password.** Storage zone → FTP & API Access →
   *Password*. This is the value for `BUNNY_TVET_KEY`.

   It is **not** the account-level API key, **not** Ehel's `BUNNY_KEY`, and
   **not** Quraan's `BUNNY_STORAGE_ACCESS_KEY`. Each school in this repo has
   its own, precisely so one school's tree can never land in another's zone.

3. **CDN → Add Pull Zone**, origin = the `adowtvet` storage zone. The
   hostname it gives you (`adowtvet.b-cdn.net`) is `cdnHost`. A custom domain
   can be attached later without re-uploading anything.

## D. The dry run, which is free and the default

```powershell
node tools/upload-adow-to-bunny.js
```

This uploader is **dry by default** — unusually for this repo, and
deliberately. The others upload on a bare invocation, which is how a stray
probe once re-uploaded all six Ehel subjects. It also **refuses unrecognised
arguments** rather than ignoring them, so a typo in `--confirm` is a refusal
and never a surprise upload.

Read the plan it prints. Three tiers actually go up:

| tier | what |
| --- | --- |
| zone root | `catalog.json` and `catalog-<digest>.json` |
| `content/<course>/…` | `course-manifest.json` and each unit's data |
| `app/…` | the lesson build — `.html .css .js .svg .png .woff2 .mp4 .vtt .jpg` |

`media/` is not used: nothing in this school has media of its own. The `app/`
tier is what makes the CDN a browsable site rather than a catalogue of JSON,
and it carries the film, its captions and the slide deck.

## E. The real upload

Run this yourself — uploads from this session are refused:

```powershell
node tools/upload-adow-to-bunny.js --confirm > adow-upload.log 2>&1; Get-Content adow-upload.log
```

**Redirect to a file; never pipe it through `head` or `tail`.** A pipe that
closes early kills the upload mid-run with SIGPIPE, and these tools print
their summary first, so a pipe keeping the end discards the part that answers
your question.

`--force` re-sends everything by ignoring `.bunny-adow-manifest.json`. You
should not need it on a first upload, because the manifest does not exist yet.

## F. Proving it worked

Three checks, in this order:

```powershell
Test-Path .bunny-adow-manifest.json                       # the manifest was written
(Invoke-WebRequest "https://adowtvet.b-cdn.net/catalog.json").StatusCode
(Invoke-WebRequest "https://adowtvet.b-cdn.net/app/index.html").StatusCode
```

**Do not probe any path before its upload lands.** An edge read is a write to
the cache: a 404 you mint by checking early is edge-cached, and on a version or
media path that is roughly a year you cannot purge from here. Ask *storage*
with the access key if you need to know whether a file is absent — a storage
read is passive. And a storage listing of a directory that does not exist
returns HTTP 200 with an empty array, so read the body and count objects
rather than trusting the status.

Then open the lesson itself and click through it, because a file being present
proves presence, not correctness:

```
https://adowtvet.b-cdn.net/app/carpentry/tools-and-joints-app/marking-out-and-cutting-a-halving-joint.html
```

Check the film plays, and that **"Step through it at your own pace"** opens the
30-slide deck.

## G. What comes after

The zone makes the content reachable. It does not yet make the school exist in
Moodle. That is the next step and it is small: add this school's
content-addressed catalogue URL as **a new line** in the Moodle setting
`local_prequran/catalog_source_url`, which takes one URL per line, one per
consumer school.

Use `catalog-<digest>.json`, **never the plain `catalog.json`** — the plain
name is served with a 30-day max-age and cannot be purged, so a catalogue
change would not be seen for a month.

`tools/generate-adow-catalog.js` writes both, and Quraan Academy is the proof
that this whole path works end to end.

## H. The custom domain, and why it is not cosmetic

**Measured on 2026-09-26: every asset on `*.b-cdn.net` was refused by a browser
content blocker** with `net::ERR_BLOCKED_BY_CLIENT`. Not the HTML — a learner
navigates to that and it arrives — but every stylesheet and script it pulls.
The result is not a degraded page, it is a dead one: `window.CARP` is never
defined, the lecture step builds nothing, and the learner sees a lesson with no
film, no demonstration clip, no controls and no styling. Opening the mp4 URL
directly failed the same way while `curl` pulled the identical 2,910,859 bytes,
so the block covers media as well as code.

**This is not a Professor Adow problem.** The same browser, the same minute,
loaded `ehelacademy.b-cdn.net` and got 0 scripts and the same error. Ehel
Academy's live school is already exposed to it. `b-cdn.net` is a shared CDN
hostname used by a great many sites, so it lands on blocklists on the strength
of what other people serve from it, and nothing we put in the zone changes that.

A custom domain is not on those lists, because it is ours alone.

### H.1 What has to change — almost nothing

This was checked rather than assumed:

| thing | depends on the hostname? |
| --- | --- |
| every page, script and stylesheet | **No.** All paths are relative (`../lesson-kit/lib/kit.js`) |
| `catalog.json` | **No.** Zero occurrences of the hostname |
| `cdnHost` in `school.config.json` | only to PRINT the URL after an upload |
| `appDomain` in `school.config.json` | nothing reads it; the guard exists so the decision is not forgotten |
| the Moodle `catalog_source_url` line | yes — but the old line keeps working |

**So the switch needs no re-upload and no rebuild.** The zone keeps its
content; a second hostname simply starts serving it.

### H.2 In the domain registrar

1. Register a **Professor Adow** domain, or pick a subdomain of one you own.
   It must not be an Ehel subdomain: this school is deliberately separate, which
   is the whole reason it has its own zone, catalogue and consumer record.
2. Add a **CNAME** record pointing the hostname you will serve from at the pull
   zone:

   ```
   app.<your-domain>      CNAME   adowtvet.b-cdn.net
   ```

   Use a subdomain (`app.`, `learn.`, `school.`) rather than the bare domain:
   a bare domain often cannot take a CNAME, and you will want the root for a
   website later.

### H.3 In the Bunny dashboard

3. Pull zone `adowtvet` → **Hostnames** (may be "Custom Hostnames" or under
   General) → **Add Hostname**, and enter the same name you pointed at it.
   Bunny verifies the CNAME; if it complains, DNS has not propagated yet —
   wait rather than retrying in a loop.
4. On that hostname, switch on **Force SSL** and use **Bunny's free Let's
   Encrypt certificate**. Do not skip this: the pages are served over https
   today, and a mixed-content page is a second way to get a blank lesson.
5. Leave `adowtvet.b-cdn.net` attached. Both hostnames serve the same zone, so
   nothing that already points at the old name breaks while you move over.

### H.4 In the repo

6. `src/prototypes/professor-adow-tvet/school.config.json`:

   ```json
   "cdnHost":   "app.<your-domain>",
   "appDomain": "app.<your-domain>",
   ```

   `appDomain` stops being a stand-in at this point, which is what the Phase 0
   guard was holding the place for.
7. Re-run `npm run deploy:adow` **only when content has actually changed**. The
   hostname change alone does not require it — the next ordinary deploy will
   print the new URL.

### H.5 In Moodle

8. Add the catalogue line under its NEW hostname in
   `local_prequran/catalog_source_url` (the setting is on the **EduPlatform**
   plugin page — `local_prequran` is its component name, not its label), and
   remove the `b-cdn.net` line for this school only. One URL per line; never
   touch Ehel's or Quraan's.

### H.6 Prove it

9. From a browser **with the blocker still switched on**, open a lesson on the
   new hostname and check the console is clean and a film plays. That is the
   whole point of the exercise, and testing with the blocker off proves
   nothing.

### H.7 The same argument applies to Ehel Academy

Ehel is served from `ehelacademy.b-cdn.net` and was measured failing in exactly
this way. Whatever is decided here should be decided there too, and it is the
larger school. That is a separate lane and is not done from this one.
