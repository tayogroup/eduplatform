# The prompt this build was made from (improved)

The request arrived as one sentence:

> Build a new Grade 1 science model, modeling the design/style/UI after
> english/grade-1-v2, with interactive content, interactions with kids, visual
> examples, and experimentation and demonstration, strength, and quality after
> mathematics/grade-1-v2. Build the content using the Curriculum Framework
> Cambridge Primary Science 0097. Create an improved prompt.

Below is the version that states what that sentence assumes, what it leaves
open, and the checks that decide whether it was done. It is written so it can
be reused for the next subject or stage by changing the named things.

---

## Build a Grade 1 Science standalone lesson course for Ehel Academy

### What to build

A **standalone lesson build** at `src/prototypes/ehel-academy/science/grade-1-app/`,
the third of its kind after `mathematics/grade-1-app/g1v2` (live at
`app/mathematics/grade-1-v2`) and `english/grade-1-app` (live at
`app/english/grade-1-v2`). One self-contained HTML page per lesson plus a hub,
each page carrying its own CSS, its own activity JS and its own copy of the
voice engine, bypassing `shell/course-app.js`. Generated by a Python builder
from authored content, then wired by the shared pipeline in
`mathematics/lesson-app-tools/` and gated by its `check-lessons.py`.

**Design, style and UI: the English build's, which is the Mathematics build's.**
Lift `lib/lesson.css` (the dark Wehel palette, the deck, the dot rail, the gold
action colour, the voice bar), `lib/voice.js` and `lib/deck.js` verbatim from
`english/grade-1-app/lib/`. Add science-specific styles in a separate file and
never a new hue: gold is the action, teal is the voice and the taught thing,
coral is the thing being pointed at, good/bad are the only verdicts.

**Interaction strength and quality: the Mathematics build's.** Every step is a
manipulative the child drives, not a page they read: a state machine with a
button, a thing that moves, a verdict spoken and shown. Each step has a
four-move authored explainer behind the Explain button (name the idea, show it
on this step's content, warn about the slip children make here, hand back with
one thing to try) and a `data-say` instruction spoken on arrival. Sound is
synthesised where the lesson is about sound; nothing is recorded.

### The content: Cambridge Primary Science 0097, Stage 1, all of it

- Extract the framework from the published PDF with
  `tools/extract-cambridge-science-framework.py --code 0097` into
  `src/curriculum/cambridge-science-0097.json` and make
  `npm run validate:frameworks` pass on it. Stage 1 has **35** objectives
  across six strands.
- Organise lessons by the framework's **sub-strands**, not by the existing
  six-unit course under `science/grade-1/data/` (that course is 0846-aligned
  and its explorations say "follow the plan in your experiments book"). Eight
  lessons: living/never alive and needs; parts of a plant; body and senses;
  materials; forces and floating; sound; electricity and magnets; Earth and
  Sun.
- **Every step names the objective codes it exercises**, the builder refuses a
  code Stage 1 does not publish, and a gate on the BUILT pages fails if any of
  the 35 is reached by no step. Thinking and Working Scientifically (8) and
  Science in Context (4) are objectives too, not decoration: every lesson has a
  predict → try → what happened → did it match experiment (1TWSp.02, 1TWSc.04,
  1TWSa.01), most have a sort (1TWSc.01), a record-in-a-table (1TWSc.05), a
  non-standard measurement (1TWSc.03), an ask-a-question (1TWSp.01), an
  equipment step (1TWSc.02), and a Science in Context card set (1SIC.01-04).
- Language: British English, five-to-six-year-old reading level, the learner
  addressed as "you", one idea per sentence. Distractors are things the child
  is also learning, never nonsense.

### The experiment shape, which is the point

An experiment step is four phases the child cannot skip: **Predict** (a choice,
recorded), **Try it** (a simulation with real state the child advances: days,
steps, catches, hours), **What happened?** (a choice about what the simulation
actually did), **Did it match?** (Yes/No about their own prediction, which the
page knows, so a wrong prediction honestly answered is right and is praised:
"scientists learn most when they are surprised"). Per-item experiments
(float/sink, magnet) predict before every drop. Record steps are filled from
what the simulation did, so recording is recording and not guessing.

### Wiring and progress

- `app.config.json` describes the build for the shared tools; `progressUnitPrefix`
  is `l` because these lessons are not the shell course's units (read THE UNIT
  PROBLEM in `wire-progress.py`); `courseKey` is the shell's `ehel-sci-g01`.
- Run, in order: `build-lessons.py`, `build-hub.py`, then `wire-navigation`,
  `wire-platform-controls`, `preload-platform`, `wire-progress`,
  `add-header-bars`, `check-lessons`, then the build's own `check-coverage.py`.
- Do NOT deploy. `deploy.mjs --app .` plans; `--upload` is an owner decision,
  and routing Grade 1 Science here is a Moodle setting nobody's course points at
  yet.

### Definition of done

1. `build-lessons.py` builds 8 pages with 0 refusals and reports 35/35.
2. `check-lessons.py` and `check-coverage.py` exit 0; `validate:frameworks`
   exits 0 with the new file present.
3. Every inline classic script parses under `node --check`.
4. Each gate is mutation-tested: a dropped objective, an unpublished code, a
   quiz with no key and a sort into a missing bin must each fail
   `check-coverage.py`, with the page restored byte-identical afterwards.
5. Each lesson is opened in a browser from a static server and every step is
   driven to completion; the dot rail, the header progress and the sticker
   shelf agree. The only console errors are the five platform modules that
   404 in local dev by design.
6. A README beside the build says what it is, what is generated, what will
   bite, and what was deliberately not done.

### What is deliberately out of scope

Deploying; routing a learner; recorded narration (the voice engine speaks);
reusing the 0846 course's text; the Word-pack pipeline; anything at Stage 2+.

### Why the original sentence needed this

- "Grade 1 science model" could mean a content model (the JSON the shell
  renders) or a lesson app. The two reference builds settle it: a standalone
  lesson app.
- "modeling the design after english/grade-1-v2" and "quality after
  mathematics/grade-1-v2" are one instruction, because English's design IS
  Mathematics' design lifted verbatim; the difference between the two builds is
  that English plays recordings and Mathematics drives manipulatives. Science
  has no recordings, so it is Mathematics-shaped throughout.
- "Curriculum Framework 0097" is not what `science/grade-1/data` declares
  (0846), so building from the existing course would have been building to the
  wrong framework. The framework had to be extracted first and gated last.
- "experimentation and demonstration" is exactly the Thinking and Working
  Scientifically strand, so it is stated as objectives with codes, which is
  what lets a gate say whether it was done.
