# The prompt this build was made from (improved)

The request arrived as one sentence, with the framework PDF attached:

> Build a new Grade 1 computing model, modeling the design/style/UI after
> english/grade-1-v2, with interactive content, interactions with kids, visual
> examples, and experimentation, and demonstration, strength, and quality after
> the new math and science. Build the content using the Curriculum Framework
> Cambridge Primary Computing 0059. Create an improved prompt.

Below is the version that states what that sentence assumes, what it leaves
open, and the checks that decide whether it was done. It is written so it can
be reused for the next subject or stage by changing the named things, and it
is the Science build's prompt (`science/grade-1-app/PROMPT.md`) with the
computing-shaped parts stated.

---

## Build a Grade 1 Computing standalone lesson course for Ehel Academy

### What to build

A **standalone lesson build** at `src/prototypes/ehel-academy/computing/grade-1-app/`,
the fourth of its kind after `mathematics/grade-1-app/g1v2` (live at
`app/mathematics/grade-1-v2`), `english/grade-1-app` (live at
`app/english/grade-1-v2`) and `science/grade-1-app` (live at
`app/science/grade-1-v2`). One self-contained HTML page per lesson plus a hub,
each page carrying its own CSS, its own activity JS and its own copy of the
voice engine, bypassing `shell/course-app.js`. Generated by a Python kit from
authored content, then wired by the shared pipeline in
`mathematics/lesson-app-tools/` and gated by its `check-lessons.py`.

**Make it its own kit, `computing/lesson-kit/`, on the Science kit's shape.**
Do not generalise `science/lesson-kit/` to a second subject: it is live for two
grades, another session is extending it for Stage 3, and its safety proof was a
byte-identical rebuild of its own pages. Copy the three design files
(`lesson.css`, `voice.js`, `deck.js`) verbatim and give computing its own
`computing.js`, `computing.css`, builders and gate, so a change to either kit
cannot reach the other's live pages.

**Design, style and UI: the English build's, which is the Mathematics build's.**
The dark Wehel palette, the deck, the dot rail, the gold action colour, the
voice bar, the two header bars from the shared tool. Add computing-specific
styles in a separate file and never a new hue: gold is the action, teal is the
voice and the taught thing, coral is the thing being pointed at, plum is a
second series, good/bad are the only verdicts. The block categories borrow the
same four.

**Interaction strength and quality: the Mathematics and Science builds'.**
Every step is a machine the child drives, not a page they read, and the machine
only does what it is told: Robo goes where the program says and nowhere else;
the block program runs exactly the blocks placed, so a wrong result is the
child's own program to read; the everyday-algorithm scenes paint in the order
the steps were tapped, so shoes before socks draws socks OVER shoes. Each step
has the four-move authored explainer behind Explain (name the idea, show it on
this step's content, warn about the slip children make here, hand back with one
thing to try) and a `data-say` line spoken on arrival. Sound is synthesised;
nothing is recorded.

### The content: Cambridge Primary Computing 0059, Stage 1, all of it

- Extract the framework from the published PDF with a new
  `tools/extract-cambridge-computing-framework.py` into
  `src/curriculum/cambridge-computing-0059.json`, teach
  `validate-curriculum-framework.mjs` the new file and the new code shape
  (`1CT.05`, `1P.01`, `1MD.03`, `1DC.02`, `1CS.06` — no sub-strands), and make
  `npm run validate:frameworks` pass with a strand check that is real for it.
  Stage 1 has **28** objectives across five strands.
- Organise lessons by **strand**, not by the eleven units of the Word-pack
  course under `computing/grade-1/data/` (that course declares a different
  framework code and is built from teacher guides). Eight lessons: what an
  algorithm is; order and bugs in algorithms; directions on a grid; algorithm
  to program; bugs and debugging; data; networks and the internet; computer
  systems.
- **Every step names the objective codes it exercises**, the builder refuses a
  code Stage 1 does not publish, and a gate on the BUILT pages fails if any of
  the 28 is reached by no step. Computational Thinking and Programming are
  behaviours, not labels: following an algorithm is tapping its steps in order
  and watching the scene; a bug is found in a running program the child just
  watched go wrong; a prediction is made about a program before Run is pressed.
- Language: British English, five-to-six-year-old reading level, the learner
  addressed as "you", one idea per sentence. Distractors are things the child
  is also learning, never nonsense. Home projects are **unplugged**, as the
  framework itself says Stage 1 mostly is.

### The shapes that are the point

- **Robo (1CT.03, 1P.02, 1P.03, 1P.05):** Bee-Bot rules on a grid — forward and
  backwards move one square the way Robo faces, the turns spin on the spot, a
  wall or the edge is a bump. The child builds a program of instruction chips
  and presses Go; predict levels give a program and ask where Robo stops
  BEFORE it runs.
- **Blocks (1P.01, 1P.02, 1P.05):** an algorithm in words is rebuilt as blocks;
  Run executes them on a sprite; the page reads back what the program DID
  against what the algorithm ASKED, and a wrong program is edited and run
  again, never marked.
- **Debugging (1P.04, 1P.06, 1P.07):** run first, watch it go wrong, tap the
  block that is the bug, choose the fix, run again.
- **Data (1MD.01–04):** six people state their answers, the child records each
  on a form and the table fills from what was submitted; the questions asked
  of that table are keyed by arithmetic the builder re-computes, not by claim.
- **Networks (1DC.01–04):** devices are connected to a router (a solid line for
  a wire, a dashed one for wireless), things are sent across the network, and
  the child switches the internet OFF and predicts which apps still work.

### Wiring and progress

- `app.config.json` describes the build for the shared tools; `progressUnitPrefix`
  is `l` because these lessons are not the shell course's units (read THE UNIT
  PROBLEM in `wire-progress.py`); `courseKey` is the shell's `ehel-comp-g01`.
- Run, in order: `build-lessons.py`, `build-hub.py`, then `wire-navigation`,
  `wire-platform-controls`, `preload-platform`, `wire-progress`,
  `add-header-bars`, `check-lessons`, then the kit's own `check-coverage.py`.
- Do NOT deploy. `deploy.mjs --app .` plans; `--upload` is an owner decision,
  and routing Grade 1 Computing here is a Moodle setting nobody's course points
  at yet.

### Definition of done

1. `build-lessons.py` builds 8 pages with 0 refusals and reports 28/28.
2. `check-lessons.py` and `check-coverage.py` exit 0; `validate:frameworks`
   exits 0 with the new file present.
3. Every inline classic script parses under `node --check`.
4. The gate is mutation-tested and each of these must fail it, with the pages
   restored byte-identical afterwards: a lesson losing an objective, an
   unpublished code, a quiz with no key, a sort into a missing bin, a Robo
   solution that misses the flower, a predict answer that disagrees with the
   program, a table key that disagrees with the rows, a debug fix that does not
   make the expected program, a lesson under its floor.
5. Each lesson is opened in a browser from a static server and every step is
   driven to completion; the dot rail, the header progress and the sticker
   shelf agree. The only console errors are the five platform modules that
   404 in local dev by design. No step overflows at 375px.
6. A README beside the build says what it is, what is generated, what will
   bite, and what was deliberately not done.

### What is deliberately out of scope

Deploying; routing a learner; recorded narration (the voice engine speaks);
reusing the Word-pack course's text; anything at Stage 2+; a Scratch Jr
embed (the framework recommends the real tool for on-screen programming, and a
self-contained page cannot carry it).

### Why the original sentence needed this

- "Grade 1 computing model" could mean a content model (the JSON the shell
  renders) or a lesson app. The three reference builds settle it: a standalone
  lesson app.
- "modeling the design after english/grade-1-v2" and "quality after the new
  math and science" are one instruction, because the three builds share one
  design and differ only in what the child drives. Computing has no recordings
  and no experiments; it has machines that only do what they are told, so it is
  Mathematics-shaped throughout.
- "Curriculum Framework 0059" is not what `computing/grade-1/data` declares, so
  building from the existing course would have been building to the wrong
  framework. The framework had to be extracted first and gated last.
- "experimentation, and demonstration" in computing is running a program to
  see what it does, which is exactly 1P.03 and 1P.05, so it is stated as
  objectives with codes, which is what lets a gate say whether it was done.
